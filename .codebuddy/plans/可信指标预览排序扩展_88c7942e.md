## 产品概述

在"编辑可信指标 → 计算口径 → 实时数据预览"面板中，现有"选择预览维度"多选下拉框基础上，新增排序能力：用户可选择按哪个字段排序（预览输出的维度字段或指标列），并可切换升序/降序，切换后立即刷新预览数据与 SQL。

## 核心功能

- 新增"排序字段"单选下拉框：选项为当前已选预览维度 + 指标列，可清空恢复默认排序（按指标列降序）
- 新增升序/降序切换控件（默认降序），与排序字段联动触发预览刷新
- 预览请求携带排序参数，后端按所选字段与方向生成 ORDER BY 并执行
- 维度选择变化导致排序字段失效时，自动清理排序字段并刷新，保证请求始终合法
- 后端保持向后兼容：未传排序参数时行为与现状完全一致（按指标列降序）

## 技术栈

- 前端：Vue 3 + TypeScript + Element Plus（^2.7.8，el-radio-button 使用 value 属性）
- 后端：FastAPI + Pydantic v2 + SQLAlchemy 2，测试用 pytest
- 无新增依赖，完全复用现有预览链路（POST /api/metrics/{id}/preview）

## 实现方案

### 设计要点

1. **请求契约扩展**：`MetricPreviewRequest`（backend/app/schemas/metric.py 第 128-132 行）新增 `order_by: Optional[str] = None` 与 `order_direction: str = "desc"`（field_validator 规范化大小写，仅接受 asc/desc）。`order_by` 传值语义与前端维度下拉框一致（字段原始名，可含表前缀如 `sales.region`；指标列传指标名），后端内部映射为 SELECT 输出别名后再排序。
2. **ORDER BY 生成**：`_metric_preview_plan`（backend/app/api/metrics.py 第 532-588 行）中把硬编码的 `ORDER BY {_quote_alias(metric_alias)} DESC`（第 580 行）改为解析 `payload.order_by`：

- 命中某个已选维度项的 `field` 或 `label` → `ORDER BY _quote_alias(label)`（维度列 SELECT 均以 label 别名输出，派生列只能按别名排序，统一用别名最稳妥）
- 命中指标别名 → `ORDER BY _quote_alias(metric_alias)`
- 为空 → 保持默认 `ORDER BY _quote_alias(metric_alias) DESC`（完全向后兼容）
- 均未命中 → 抛 HTTPException 400 "排序字段不合法"
- 方向统一大写输出 ASC/DESC，计划返回结构增加 order_by/order_direction，preview_metric 响应 query（第 1473-1478 行）同步透传

3. **前端交互**（MetricSettings.vue）：

- 状态：`metricPreviewOrderBy = ref("")`、`metricPreviewOrderDirection = ref<"asc" | "desc">("desc")`
- 排序字段选项 computed：当前 `metricPreviewDimensions` 中选中的维度映射到 `dimensionFieldOptions` 的 `name`（选项标签用 `fieldOptionLabel`）+ 指标列 `form.name`
- 维度 `@change` 改为 handler：先清理不在候选中或已失效的排序字段，再调 `fetchMetricPreview`
- 排序字段与方向 `@change` 均触发 `fetchMetricPreview`；请求体增加 `order_by: metricPreviewOrderBy.value || null` 与 `order_direction`
- `resetMetricPreview`（第 2731-2738 行）同步重置排序状态
- 模板在 `.metric-preview-controls`（第 795 行）维度下拉框后追加 `el-select`（clearable，placeholder 如"默认排序（按指标）"）与 `el-radio-group` + `el-radio-button`（升序/降序），新增 `.metric-preview-order` 宽度样式

4. **性能与安全**：预览 limit ≤ 200，ORDER BY 作用于聚合后的小结果集，开销可忽略；所有排序目标仅限 SELECT 输出的合法别名（经 `_quote_alias` 转义，第 475-476 行），杜绝 SQL 注入；不改动无关注册链路。

## 实施注意事项

- 后端 `model_config = ConfigDict(extra="forbid")`，新增字段必须同步 schema 与前端请求体，避免 422
- 排序字段选项值必须与后端校验口径一致：维度传 `field.name`（含表前缀的原始名），指标传 `form.name`（编辑态与数据库 metric.name 一致）
- 维度下拉框 `@change="fetchMetricPreview"`（第 806 行）需改为先清理失效排序字段再刷新的 handler，避免发出含非法 order_by 的请求
- 执行后按 AGENTS.md 运行检查：后端 `uv run pytest tests/test_metric_preview.py` + `uv run ruff check .`，前端 `npm run typecheck` + `npm run test:static`
