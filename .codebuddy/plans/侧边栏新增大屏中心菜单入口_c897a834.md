## 用户需求

前端侧边栏缺少"大屏中心"菜单入口，导致无法从界面进入大屏中心删除"跨境电商全球作战大屏"（该大屏来自 `demo_data_crossborder.sql` 演示数据，同时存在于 `big_screens` 表 id=100 和 `data_assets` 表 id=108 数据目录条目中，通过大屏中心删除可级联清理）。

## 核心功能

- 在侧边栏"BI 分析"分组中新增"大屏中心"菜单项，路由指向已存在的 `/big-screen-center` 页面
- 登录用户点击菜单可进入大屏中心，找到"跨境电商全球作战大屏"并删除，数据目录中的对应条目自动同步清理

## 技术栈

- Vue 3 + TypeScript + Element Plus（沿用现有前端架构，仅修改 1 个文件）

## 实施方案

### 修改文件

仅修改 `frontend/src/layouts/MainLayout.vue`，两处改动：

1. **图标导入**：在现有 `@element-plus/icons-vue` 导入列表中新增 `Monitor` 图标（当前列表为 `DataLine, ChatDotRound, Coin, User, OfficeBuilding, TrendCharts, Setting, Refresh, SwitchButton, Bell, AlarmClock, Grid, FolderOpened, Document, Fold, Expand, Tickets, SetUp, MagicStick, Memo`，不含 Monitor）。

2. **菜单项**：在 `menuEntries` 的"BI 分析"分组（key: `bi-assets`）items 中，紧跟"看板中心"之后追加：

```ts
{ path: "/big-screen-center", label: "大屏中心", icon: Monitor },
```

### 关键决策

- **不加 `roles` 限制**：路由 `/big-screen-center` 本身对全部登录用户开放（无 `meta.requiredRole`）；`BigScreenCenter.vue` 的数据列表已由后端 `list_big_screens` 的 `_apply_visibility` 按角色过滤（普通用户仅见 published/本人拥有的），删除按钮由 `_can_manage`（super_admin / 同组织 org_admin / owner）控制。菜单层无需额外收紧，与"看板中心"等既有菜单一致。
- **保留 `hiddenPageTitles` 中 `/big-screen-center` 映射**：`pageTitleMap` 优先命中 menuEntries，该行保留无副作用，避免多余改动。
- **不修改路由与后端**：`/big-screen-center` 路由已注册，后端 `DELETE /api/big-screens/{id}` 已含 `delete_catalog_asset` 级联清理，前端菜单补齐即可闭环。

## 实施注意

- 菜单项插入位置保持"看板中心"之后，符合 BI 分析分组现有排序逻辑。
- 不改动其他菜单项、不影响折叠/展开逻辑（`el-menu` 自动处理）。
- 修改后需运行 `cd frontend && npm run typecheck` 验证类型，涉及页面交互可启动 dev 后人工确认。
