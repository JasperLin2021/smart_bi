## 产品概述

修复自助分析页面缺少删除已保存分析入口的问题。为"已保存分析"面板的每个视图卡片补充删除按钮，支持删除已保存的自助分析视图。

## 核心功能

- 在自助分析"已保存分析"面板为每个视图卡片新增"删除"操作按钮
- 删除按钮仅对 org_admin / super_admin 角色显示（用户已确认选择"仅管理员可删"方案，不修改后端权限模板）
- 点击删除时弹出二次确认对话框，防止误删
- 确认后调用后端已有的删除接口，删除成功刷新已保存分析列表并给出成功提示
- 删除失败时展示后端返回的错误信息

## 技术栈

- 仅修改前端 Vue 3 + TypeScript + Element Plus 项目，沿用现有 Composition API 与 axios 调用模式
- 后端 `DELETE /api/analysis-views/{view_id}` 接口已存在（`backend/app/api/analysis_views.py` 788-798 行），无需改动
- 角色判断沿用 `frontend/src/store/auth.ts` 的 `isOrgAdmin` 模式（role 为 org_admin 或 super_admin）

## 实现方案

在 `frontend/src/views/AnalysisWorkbench.vue` 的"已保存分析"卡片操作区（saved-actions，第 265-278 行）追加删除按钮，复用已导入的 `Delete` 图标。删除逻辑使用 `ElMessageBox.confirm` 二次确认，确认后调用 `axios.delete(/api/analysis-views/${view.id})`。

关键设计决策：

- **权限控制**：通过 `computed` 判断 `authStore.profile?.role` 是否属于 `org_admin`/`super_admin`，用 `v-if` 控制按钮显隐；后端 `_get_manageable_view` 已做归属校验，双重保障
- **删除后处理**：沿用项目现有模式（copy/publish 成功后均调用 `loadAll()`）刷新列表；若当前编辑中的视图（form.id === view.id）被删除，将 form.id 置空，避免后续保存时对已删除记录发起 PUT 请求
- **取消处理**：用户取消确认框时静默返回，不产生请求
- **错误处理**：失败时优先展示后端 `detail` 信息，兜底为"删除失败"，与现有 catch 模式一致

## 实施要点

- 需补充导入：`ElMessageBox`（追加到现有 `import { ElMessage } from "element-plus"`）与 `useAuthStore`
- `Delete` 图标已导入（第 307 行），无需重复导入
- 按钮样式使用 `text type="danger"`，与筛选/排序行的删除按钮风格一致
- 不改动后端、不动权限模板、不涉及 Agent 服务
- 验证：运行 `npm run typecheck` 与 `npm run build`；若环境可访问可补 `npm run test:ui`
