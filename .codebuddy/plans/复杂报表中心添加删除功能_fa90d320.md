## 产品概述

用户尝试删除数据集「跨境电商订单分析」时被"复杂报表（商品价格调整表）引用"拦截，询问复杂报表在哪里删除、是否有入口及按钮。经核实：后端删除接口已存在，但前端复杂报表中心**没有删除按钮与任何删除入口**，需补充修复。修复后管理员可在界面删除复杂报表，从而解除其对数据集的引用，再删除数据集。

## 核心功能

- 在复杂报表中心（ReportCenter.vue）操作列为每个报表新增"删除"按钮
- 删除按钮仅对 org_admin / super_admin 角色显示（沿用此前"仅管理员可删"的决策，不修改后端权限模板）
- 点击删除时弹出二次确认对话框，明确提示不可恢复、关联的填报记录/运行记录/版本将一并删除
- 确认后调用后端已有的删除接口，删除成功后刷新报表列表并给出成功提示
- 删除失败时展示后端返回的错误信息

## 技术栈

- 仅修改前端 Vue 3 + TypeScript + Element Plus 项目（`frontend/src/views/ReportCenter.vue`），沿用现有 Composition API 与 axios 调用模式
- 后端 `DELETE /api/report-templates/{template_id}` 接口已存在（`backend/app/api/report_templates.py` 208-233 行），会级联删除填报记录、运行记录、版本并记录审计日志，无需改动
- 角色判断沿用 `frontend/src/store/auth.ts` 的 `isOrgAdmin` getter，与自助分析 `AnalysisWorkbench.vue` 的 `canDeleteAnalysis`、ETL `DataPipelines.vue` 的 `canDeletePipeline` 实现模式一致

## 实现方案

在 `ReportCenter.vue` 操作列（81-108 行）追加"删除"按钮，点击调用新增的 `deleteReport` 方法。

### 关键设计决策

- **按钮位置**：置于操作列普通分支（非 ai_html）的导出按钮之后，使用 `text type="danger" :icon="Delete"` 样式；操作列 width 由 260 加宽至约 300 容纳新按钮。ai_html 报表（AI 生成模板）也一并提供删除（其当前仅有预览按钮）。
- **权限控制**：`v-if="canDeleteReport"`（`authStore.isOrgAdmin`）控制显隐；后端 `_get_template_for_user` 已做归属校验，双重保障。
- **二次确认**：`ElMessageBox.confirm` 提示"此操作不可恢复，关联的填报记录、运行记录与历史版本将一并删除"，与后端级联行为一致；用户取消时静默返回不发起请求。
- **删除后处理**：成功后调用现有 `loadAll()` 刷新列表（reports 与 datasets）。
- **错误处理**：失败时优先展示后端 `detail`，兜底"删除失败"，与页面现有 catch 模式一致。

### 实施要点

- 需补充导入：`ElMessageBox`（追加到 174 行 `import { ElMessage } from "element-plus"`）、`import { useAuthStore } from "@/store/auth"`、`Delete` 图标（追加到 175 行 icons 导入）
- 新增 `const authStore = useAuthStore()` 与 `const canDeleteReport = computed(() => authStore.isOrgAdmin)`（放在 `const router = useRouter()` 附近）
- `deleteReport(row: ReportTemplate)` 方法放置于 `exportTemplate`（324-334 行）之后，保持操作方法集中
- 不改动后端、不动权限模板、不涉及 Agent 服务
- 验证：`cd frontend && npm run typecheck` 与 `npm run build`
