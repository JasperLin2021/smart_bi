## 产品概述

为可视化 ETL 工作台补充删除管道功能。目前可视化 ETL 页面只有画布内"删除节点"操作，无法删除已保存的管道。本次修复在顶部工具栏新增"删除"按钮，支持删除选中的已保存管道。

## 核心功能

- 顶部工具栏新增"删除"按钮，删除当前选中的管道
- 删除按钮仅对 org_admin / super_admin 角色显示（沿用此前"仅管理员可删"的决策，不修改后端权限模板）
- 点击删除时弹出二次确认对话框，明确提示删除不可恢复、关联的运行记录与质量规则将一并删除
- 确认后调用后端已有删除接口，删除成功后刷新管道列表并给出成功提示
- 删除失败时展示后端返回的错误信息

## 技术栈

- 仅修改前端 Vue 3 + TypeScript + Element Plus 项目（`frontend/src/views/DataPipelines.vue`），沿用现有 Composition API 与 axios 调用模式
- 后端 `DELETE /api/pipelines/{pipeline_id}` 接口已存在（`backend/app/api/pipelines.py` 1176-1200 行），会级联删除运行记录与质量规则、移除调度并记录审计日志，无需改动
- 角色判断沿用 `frontend/src/store/auth.ts` 的 `isOrgAdmin` getter（role 为 org_admin 或 super_admin），与自助分析 `AnalysisWorkbench.vue` 的 `canDeleteAnalysis` 实现模式一致

## 实现方案

在 `DataPipelines.vue` 顶部工具栏（`etl-mode-tabs__actions`）运行操作组与"新建管道"按钮之间新增"删除"按钮，点击调用新增的 `deleteSelectedPipeline` 方法。

### 关键设计决策

- **按钮位置**：置于顶部工具栏运行操作组（39-42 行）之后、"新建管道"（43 行）之前，使用 `type="danger" plain :icon="Delete"` 样式。原因：左侧管道列表项是 `<button class="pipeline-item">`（HTML 不允许 button 嵌套 button，无法像自助分析那样在列表项内嵌删除按钮）；而顶部工具栏集中了管道级操作（校验/预览/保存/运行），删除按钮置于此处最符合 ETL 工具操作习惯且改动最小。
- **权限控制**：`v-if="canDeletePipeline"`（`authStore.isOrgAdmin`）控制显隐，`:disabled="!selectedPipeline"` 控制可用性；后端 `_get_pipeline_for_user` 已做归属校验，双重保障。
- **二次确认**：`ElMessageBox.confirm` 提示"此操作不可恢复，关联的运行记录与质量规则将一并删除"，用户取消时静默返回不发起请求。
- **删除后处理**：删除成功后调用现有 `loadAll()` 刷新列表——该方法（2164 行）会自动处理选中态失效（保留仍存在的选中项，否则切到第一个管道或置空）；`loadSelectedDetails`（2118-2130 行）对未选中状态有 guard，会重置 runHistory/qualityRules/lineage 等状态，无空指针风险。
- **错误处理**：失败时优先展示后端 `detail`，兜底"删除失败"，与页面现有 catch 模式一致。

## 实施要点

- 需补充导入：`ElMessageBox`（追加到 1016 行 `import { ElButton, ElMessage, ElTooltip } from "element-plus"`）与 `import { useAuthStore } from "@/store/auth"`
- `Delete` 图标已导入（1025 行），无需重复导入
- 新增 `const authStore = useAuthStore()` 与 `const canDeletePipeline = computed(() => authStore.isOrgAdmin)`
- `deleteSelectedPipeline` 方法放置于 `savePipelineDag` / `publishSelectedVersion` 附近，保持管道操作方法集中
- 不改动后端、不动权限模板、不涉及 Agent 服务
- 验证：`cd frontend && npm run typecheck` 与 `npm run build`
